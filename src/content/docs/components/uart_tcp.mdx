This component allows bytes to be transferred between a hardware [UART bus](/components/uart/) and a TCP socket.
With the default protocol, data is copied unchanged in both directions.

The component can connect to a remote host (`role: client`) or listen for one incoming connection (`role: server`).
Only one TCP connection is open at a time. When `role` is `server`, a new client is accepted only after the current
connection is closed.

> [!WARNING]
> The connection is plain TCP with no encryption and no authentication; `allowed_ips` filters by address but
> does not authenticate the peer. If it is omitted, any host that can reach the port is accepted, and the
> first client to connect is the one that is served. Only use this component on a trusted network.

> [!NOTE]
> While no connection is open, bytes from the UART are discarded; a fast peer is throttled by TCP flow
> control instead of blocking the device.

> [!NOTE]
> Baud rate, data bits, parity and stop bits are set on the UART bus. They are not options of this component.

This is not Modbus TCP when `protocol` is left at `raw`: the bytes on the socket are the UART bytes,
unchanged. Set [`protocol: modbus`](#modbus-tcp) to speak Modbus TCP on the socket.

The examples assume a [UART bus](/components/uart/) with the id `uart_bus` is configured.

## Client

```yaml
# Example configuration entry
uart_tcp:
  - id: uart_tcp_1
    uart_id: uart_bus
    host: 192.0.2.20
    port: 8899
```

## Server

```yaml
# Example configuration entry
uart_tcp:
  - id: uart_tcp_1
    uart_id: uart_bus
    role: server
    port: 8899
```

## Modbus TCP

```yaml
# Example configuration entry
uart:
  - id: uart_bus
    tx_pin: GPIO17
    rx_pin: GPIO16
    baud_rate: 9600

uart_tcp:
  - uart_id: uart_bus
    role: server
    port: 502
    protocol: modbus
    allowed_ips:
      - 192.0.2.10
    send_wait_time: 2s
```

`protocol: modbus` keeps RTU on the UART and speaks Modbus TCP on the socket. Only one transaction is open.

When `role` is `server`, the TCP client is the master. Its request is written to the UART as RTU, and the
reply is sent back as Modbus TCP. If the UART device does not answer within `send_wait_time`, the client
receives exception `0x0B` (gateway target device failed to respond).

When `role` is `client`, an RTU frame from the UART is sent as a Modbus TCP request to `host`. The matching
response is written back to the UART as RTU. If `host` does not answer within `send_wait_time`, the request
is dropped and nothing is written to the UART.

`send_wait_time` should be shorter than the timeout of the Modbus TCP master. Otherwise that master has
already given up when the reply arrives. The value is independent of `send_wait_time` on a
[`modbus`](/components/modbus/) hub.

## Configuration variables

- **id** (*Optional*, [ID](/guides/configuration-types#id)): Manually specify the ID used for code generation.
- **uart_id** (**Required**, [ID](/guides/configuration-types#id)): The [UART bus](/components/uart/) to use.
- **role** (*Optional*, string): `client` or `server`. Defaults to `client`.
- **host** (**Required** when `role` is `client`, string): The host to connect to. An IP address or a hostname.
  This option cannot be used when `role` is `server`.
- **port** (**Required**, int): The TCP port to connect to, or to listen on.
- **protocol** (*Optional*, string): `raw` or `modbus`. Defaults to `raw`. `raw` copies bytes unchanged.
  `modbus` is described [above](#modbus-tcp).
- **send_wait_time** (*Optional*, [Time](/guides/configuration-types#time)): Only when `protocol` is
  `modbus`. How long to wait for the other side of one transaction. Defaults to `2s`. The option cannot be
  used when `protocol` is `raw`.
- **timeout** (*Optional*, [Time](/guides/configuration-types#time)): Close the connection when no byte has
  been sent or received for this long. `0s` leaves it open. Defaults to `0s`.
- **allowed_ips** (*Optional* when `role` is `server`, list): IPv4 addresses that may connect. A plain
  address is one host. A network is written in CIDR form, for example `192.0.2.0/24`. At most 255 entries. If
  the option is omitted, every address may connect. A rejected client is closed immediately and logged as a
  warning at most once every 5 seconds; an IPv6 client is rejected unless it carries an IPv4 mapped address, as
  on a dual stack network. This option cannot be used when `role` is `client`.
- **reconnect_interval** (*Optional*, [Time](/guides/configuration-types#time)): The time to wait before trying
  again after a failure. Defaults to `5s`.
- **connected** (*Optional*): A binary sensor that reports whether the TCP connection is established. All options
  from [Binary Sensor](/components/binary_sensor#config-binary_sensor) are supported.

## Zigbee Coordinator

This setup has not been tested with this component. Leave `protocol` at `raw`. Zigbee2MQTT can use a server of
this component instead of a serial port on the machine that runs it: in its `configuration.yaml`, set
`serial.port` to `tcp://<device ip>:<port>` and `baudrate` to the UART's baud rate. Zigbee2MQTT must be the
only TCP client. A stick on an ESP32 with USB host can be exposed the same way through
[USB Host UART](/components/usb_uart/).

> [!NOTE]
> [Ethernet](/components/ethernet/) is recommended. A coordinator drops bytes more easily on Wi-Fi than on a
> cable, and Zigbee2MQTT does not tolerate that. If Wi-Fi is the only network, do not also enable
> `bluetooth_proxy`, `esp32_ble_tracker` or `esp32_ble` on this device. They share the radio with Wi-Fi.
