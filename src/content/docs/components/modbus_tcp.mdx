This component turns Modbus RTU into Modbus TCP, and back. It does not open a socket and it has no pins.
[TCP UART](/components/tcp_uart/) and [UART TCP](/components/uart_tcp/) stay raw and copy bytes unchanged.

Set up a [TCP UART](/components/tcp_uart/) first. The hub's `uart_id` points here. `role` on this component is
who sends the Modbus request. It defaults to `client`. `role` on the `tcp_uart` only decides who opens the TCP
connection. The hub must use the same role.

When `role` is `client`, the hub writes one RTU frame. That PDU is sent as one Modbus TCP request, and the matching
response is turned back into RTU. One request is outstanding. A response with another transaction id is dropped.

```yaml
# Example configuration entry
tcp_uart:
  - id: shelly_link
    host: 192.0.2.10
    port: 502
    baud_rate: 19200

modbus_tcp:
  - id: shelly_uart
    tcp_uart_id: shelly_link

modbus:
  - uart_id: shelly_uart
```

When `role` is `server`, a request from the TCP peer is turned into one RTU frame. The hub's reply is sent back with
that request's transaction id. Address 0 is not answered.

```yaml
# Example configuration entry
tcp_uart:
  - id: inbound
    role: server
    port: 502

modbus_tcp:
  - id: bus
    tcp_uart_id: inbound
    role: server

modbus:
  - uart_id: bus
    role: server
```

The hub reads baud rate, data bits, parity and stop bits from the `tcp_uart`. Those settings are documented on
[TCP UART](/components/tcp_uart/).

## Configuration Variables

- **id** (*Optional*, [ID](/guides/configuration-types#id)): Manually specify the ID used for code generation.
  Use this ID as `uart_id` of the [Modbus](/components/modbus/) hub.
- **tcp_uart_id** (**Required**, [ID](/guides/configuration-types#id)): The raw [TCP UART](/components/tcp_uart/).
- **role** (*Optional*, string): `client` or `server`. Defaults to `client`. This is who sends the Modbus
  request, and the hub must use the same role. Who opens the socket stays on the TCP UART.
