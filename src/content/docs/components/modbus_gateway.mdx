The `modbus_gateway` component lets several Modbus clients share one RTU bus. One request is on the bus at a
time, and the response goes back only to the port that sent it. The gateway does not poll. The clients do.

Set up the [UART buses](/components/uart/) first. One bus connects the servers. Each port connects a client. A
port can instead be a UART this component creates. Use that id as the `uart_id` of a [Modbus](/components/modbus/)
hub with `role: client`. A [Modbus Controller](/components/modbus_controller/) then uses the hub like any other
bus.

The gateway loads the [Modbus](/components/modbus/) component, and that needs a `modbus:` hub. Add a port with
`id` and use it as the hub's `uart_id`, even when nothing on this device polls. This is a temporary workaround until
the Modbus helpers can be used without the hub.

```yaml
# Example configuration entry
modbus_gateway:
  - uart_id: bms_bus
    ports:
      - uart_id: inverter_bus
      - id: local_bus

modbus:
  - uart_id: local_bus
    role: client
```

## Configuration Variables

- **id** (*Optional*, [ID](/guides/configuration-types#id)): Manually specify the ID used for code generation.
- **uart_id** (**Required**, [ID](/guides/configuration-types#id)): The [UART bus](/components/uart/) the servers
  are connected to. No other component may use it in its `uart_id`.
- **response_timeout** (*Optional*, [Time](/guides/configuration-types#time)): How long to wait for a response
  once the request has left the wire, before the next port may use the bus. Defaults to `500ms`, at most
  `65535ms`. A client waits behind the other ports, so its own timeout must be longer than the number of ports
  times the sum of `response_timeout` and the quiet time below.
- **ports** (**Required**, list): The clients. At least 1 and at most 4. See [Ports](#ports).

## Ports

Set exactly one of `uart_id` and `id`.

- **uart_id** (*Optional*, [ID](/guides/configuration-types#id)): A [UART bus](/components/uart/) a client is
  connected to. Requests are read from it and the response is written back. A UART can be listed once, it cannot
  be the server bus, and no other component may use it.
- **id** (*Optional*, [ID](/guides/configuration-types#id)): Creates a UART. Use it as `uart_id` of a
  [Modbus](/components/modbus/) hub with `role: client`. The new UART copies baud rate, data bits, parity and
  stop bits from the server bus, so that bus must be a [UART bus](/components/uart/) that sets them.

Each port takes about 280 bytes of RAM, a port with `id` about 330 more, and the gateway itself about 370.

## Bus Rules

- A request starts after the bus was quiet for 3.5 characters, at least 1.75 ms. A frame longer than a UART's
  transmit FIFO goes out in parts, without a pause inside the frame.
- Each port buffers one 256-byte frame. A port that sends again before it is served keeps the latest request.
  When the buffer is full, the rest waits in the port's UART.
- A received frame ends after 3.5 quiet characters, or after 50 ms on a UART without line timing, such as a
  TCP UART.
- A response is passed on only when its address, its function and, for a read, its byte count match the
  request.
- A port that cannot take its response (not connected, buffer full, or nothing taken for 20 ms) loses it, and a
  warning is logged. The bus is free again at once.
- After a timeout the bus stays closed until it was quiet for the time of one 256-byte frame (267 ms at 9600
  baud with 8N1), and anything that arrives in that time is dropped.
- Address 0 is a broadcast. No response is expected, and the bus is held for 600 ms before the next request.
